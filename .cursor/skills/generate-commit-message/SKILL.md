# 커밋 메시지 생성 규칙

## 1. 언어 및 문체
- **언어:** 반드시 한국어로 작성합니다. 제목과 본문 모두 한국어로 쓰며, 기존 `git log`가 영어여도 영어 메시지를 쓰지 않습니다. (고유명사, CLI 명령어, 설정 키, 파일 경로는 원문 유지)
- **문체:** 간결한 문체 (~함 / 명사형 종결 혼용 가능, 경어체 불필요)

## 2. 제목(Subject) 규칙
- 형식: 반드시 `{prefix}: {요약}` 형태로 작성합니다.
- 제목 길이는 50자 내외(최대 72자)로 핵심만 작성하며, 마침표를 찍지 않습니다.
- **허용 Prefix 목록:**
  - `feat`: 사용자·운영에 보이는 기능/인프라 리소스 추가 및 변경
  - `fix`: 버그, 오동작, 배포 실패 등 문제 수정
  - `test`: 테스트 코드 및 검증 스크립트 추가/수정
  - `chore`: 빌드, CI, 의존성, 포맷팅, 문서 등 부수 작업
  - `dev`: 개발 환경, 로컬 워크플로, 개발 스크립트 등 개발자 편의 작업

## 3. 본문(Body) 규칙
- 제목만으로 변경 이유(Why)가 충분히 설명되면 본문은 과감히 생략합니다.
- 변경 이유가 명확하지 않거나, 주요 아키텍처 결정/제약사항이 있는 경우에만 1~2문장으로 **Why** 중심으로 작성합니다.
- 군더더기 표현("이 커밋은 ~합니다", "수정 요청에 따라" 등)이나 AI 생성 문구를 절대 포함하지 않습니다.
