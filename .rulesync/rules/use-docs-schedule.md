# 일정 (`docs/schedule.md`)

인덱스는 두 출처다.

| 출처 | SSOT | schedule 역할 |
|---|---|---|
| 열린 이슈 | `docs/issues/active/` | 재검토·확인·트리거. 날짜·수용 기준·재현은 **이슈 본문** |
| 운영 루프 | `docs/ops/` | 다음 실행일. 정책·체크리스트는 **ops 본문** (`use-docs-ops`) |

`docs/schedule.md`는 **언제 무엇을 볼지**만. 이슈/ops 본문을 대신하지 않는다.

## 언제 보나

- 이슈·ops를 만들거나, 상태·재검토일·다음 주기·트리거를 바꾸거나, 이슈를 `resolved`로 옮길 때 — **같은 턴에** schedule도 맞춘다
- 이슈·인프라·ops 관련 작업을 시작하기 전 — `docs/schedule.md`를 읽고 **오늘 날짜(KST)** 와 대조한다. 기한이 왔거나 지났으면 작업 들어가기 전에 한 줄로 알린다
- 사용자가 일정·다음에 할 일·재검토를 물을 때

무관한 원라이너·질문만 있는 대화에서는 스케줄을 건드리지 않는다. 기한 도래는 **알리고 확인**한다. 사용자 요청 없이 일정 때문에 이슈를 아카이브하거나 코드를 바꾸지 않는다.

## 동기화

일정표만 단독으로 고치지 않는다. 날짜를 지어내지 않는다. 이슈에 날짜가 없으면 **날짜 없음 (트리거 대기)** 에 둔다.

| 변화 | schedule |
|---|---|
| 재검토일·확인일·트리거가 생긴 열린 이슈 | 행 추가·갱신. 링크 `issues/active/…` |
| ops 등록·**다음** 주기 변경 | 행 추가·갱신. 링크 `ops/…`. 상태 칸 `ops` |
| 날짜 있음 / 없음 | **달력** / **날짜 없음 (트리거 대기)** |
| 이슈 `docs/issues/resolved` 이동, 또는 이 레포에서 할 일 없음 | **이슈 행만** 삭제 |
| ops 한 주기 완료 | 행 **삭제 금지**. 다음 날짜·할 일로 갱신 |
| 날짜·상태가 바뀜 | 이슈/ops 메타와 동일하게 |

할 일은 한 줄. 이슈 링크는 `issues/active/YYYY-MM-DD-slug.md`, ops 링크는 `ops/kebab-slug.md`. 상태 칸은 이슈 메타 `상태` 또는 `ops`.

## 하지 않을 것

- schedule을 이슈·ops 본문 SSOT로 쓰지 않는다
- 해결된 **이슈** 항목을 일정에 남기지 않는다
- 살아 있는 **ops** 행을 “이번 달 끝”이라고 삭제하지 않는다
- 이슈/ops 본문과 어긋난 날짜·상태를 일정에만 적지 않는다
