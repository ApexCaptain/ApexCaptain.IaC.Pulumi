# 커밋 메시지 규칙

## 제목(Subject)

- 제목 길이는 50자 내외(최대 72자)로 핵심만 작성하며, 마침표를 찍지 않습니다.

## 변경 범위 판단

- `[Git Diff Stat]`, `[변경 파일 목록]`, `[Git 상태]`를 **우선** 참고해 전체 변경 범위를 파악합니다.
- `common/bridged-provider/sdks/` 등 **diff 본문 제외 경로**는 `[Git Diff]`에 포함되지 않습니다. 해당 변경은 stat·파일명·경로로 판단합니다.
- `[Git Diff]`가 축약·생략되었다면, 파일명만 보고 추측하지 말고 stat·목록과 포함된 diff를 함께 판단합니다.
- 여러 주제가 섞여 있으면 **가장 중요한 사용자·운영 영향**(기능/버그 수정)을 제목에 담고, 부수 작업(README, 진단 스냅샷, 포맷)은 제목에 억지로 나열하지 않습니다.
- 주제가 명확히 분리되고 각각이 독립적이면, 커밋 분리를 권장하는 한 줄 본문을 추가할 수 있습니다. (예: `chore: README·진단 스냅샷은 별도 커밋 권장`)

## 본문(Body)

- 제목만으로 변경 이유(Why)가 충분히 설명되면 본문은 과감히 생략합니다.
- 변경 이유가 명확하지 않거나, 주요 아키텍처 결정/제약사항이 있는 경우에만 1~2문장으로 **Why** 중심으로 작성합니다.
- 본문을 쓸 때는 완결된 문장으로 작성합니다. 명사형·단편 나열로 압축하지 않습니다.

## 출력 형식

- 마크다운 코드블록(```) 없이 오직 커밋 메시지 원문 텍스트만 출력합니다.
